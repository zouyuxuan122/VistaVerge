# 全云端改造方案（赛博女友 · Cloud Edition）

> 目标：同一套"语音球 + 数字人"体验，把 LLM / STT / TTS / 口型全部搬上云端，
> 本地只留浏览器 + 一个 CPU 就能跑的编排服务。核显笔记本（Iris Xe / 16G）可完整运行。

## 1. 三条路线对比

| 路线 | 思路 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| **A. 保留 s2s 管线，三件套上云** | `--stt openai --llm_backend chat-completions --tts openai` 全指向云端 API；口型换成前端素材方案 | 改动最小（后端 handler 上游全部内置）；保留 VAD 抢答/打断手感；协议不变 | 本地仍要跑 Python 编排服务（无 GPU 需求） | ✅ **推荐** |
| B. 纯前端直连 OpenAI Realtime | 浏览器直连 `gpt-realtime`，一个 API 全包 STT+LLM+TTS | 零本地部署 | 依赖境外单一厂商；人设/音色受限；无 VAD 精调；无口型生态 | 备选 |
| C. 全托云数字人 SaaS（阿里云/腾讯/D-ID） | 整个数字人 + 对话全在云端 | 真口型 | 要企业实名/计费；失去开源性 | L2 预留接口 |

## 2. 组件映射（路线 A）

| 组件 | 本地（原方案） | 云端替换 | 备注 |
|---|---|---|---|
| LLM | llama.cpp + Qwen3-14B (8090) | **chat-completions 不变**，base_url 换 `https://api.deepseek.com/v1` / 硅基流动 / DashScope 兼容层，model 换 `deepseek-chat` 等 | 只改 3 个参数，这是方案成立的核心 |
| STT | faster-whisper large-v3 (3G 显存) | `--stt openai`，POST `/v1/audio/transcriptions`：硅基流动 `FunAudioLLM/SenseVoiceSmall`（中文强、便宜快）或 DashScope/OpenAI `whisper-1` | VAD 切句仍在本地 CPU，整句上传，天然适配 HTTP 转写接口 |
| TTS | Qwen3-TTS 1.7B (4G 显存) | `--tts openai`，POST `/v1/audio/speech`：硅基流动 `Fish-speech/fish-speech-1.5` / `FunAudioLLM/CosyVoice2-0.5B`，或 OpenAI `gpt-4o-mini-tts` | **音色克隆**：硅基流动"上传参考音频建自定义音色"（`POST /uploads/audio/voice`，直接传 `ref.wav`），voice 填 `<user>:<voice_id>`；OpenAI 无克隆但有预设音色+instructions |
| 口型 | LiveTalking + wav2lip256 (1.3G 显存, 8010) | **前端"云模式数字人层" avatar-cloud.js**（详见 §3） | 不再需要 WSL/WebRTC/权重文件 |
| VAD/打断 | s2s 内置 silero + 前端噪声门 | **原样保留**（CPU，可忽略） | `min_silence_ms=1200` 等手感参数不动 |
| 素材 | idle/listening/speaking.mp4 | 原样复用（放进前端静态目录） | ref.wav 转投云端建音色 |

本地算力需求：**从 ~17 GB 显存 → 0 GPU**（编排服务 ≈ 几百 MB 内存）。
不再需要：WSL2、llama.cpp、Qwen3 权重、faster-whisper、Qwen3-TTS、LiveTalking、wav2lip 权重。

## 3. 口型替代：三级策略

| 级别 | 方案 | 效果 | 成本 |
|---|---|---|---|
| **L0（默认）** | 状态切换：说话播 `speaking.mp4`（循环），待机播 `idle.mp4`（循环），聆听切 `listening.mp4` | 人在动、在说，嘴型不同步（即博客淘汰的 avatar-lite 方案） | 零，素材现成 |
| **L1（已实现增强）** | L0 + 音频包络驱动：截收 `output_audio.delta` 实时算 RMS，对视频层做 1.000~1.012 呼吸缩放 + 亮度微调，"嘴感"跟随语音节奏 | 暗光侧光构图下以假乱真（博客原话：暗光侧脸掩盖口型糊） | 零 GPU |
| **L2（预留）** | 云端数字人 API（阿里云虚实/腾讯智影/D-ID）：把 TTS 音频 POST 给云，收 WebRTC/HLS 真口型视频流 | 真口型同步 | 按分钟计费、需开通服务 |

avatar-cloud.js 实现同 avatar-sync.js 的"劫持 WebSocket 观察 Realtime 事件"套路，但**不吞音频**：
s2s 本地照常出声（延迟最低），数字人层只消费事件做画面。云 API 的适配口留 `window.CLOUD_AVATAR_BACKEND`。

## 4. 延迟与成本预算（SiliconFlow/DeepSeek，首轮响应）

| 阶段 | 本地原方案 | 云端方案 |
|---|---|---|
| VAD 断句 | 1200 ms（人为设定，不变） | 1200 ms |
| STT（2~4s 语料） | ~300 ms | 300~600 ms（SenseVoiceSmall 流水线快） |
| LLM 首 token | ~300 ms (14B Q4, 4090) | 300~800 ms（视网络/供应商） |
| TTS 整段合成 | ~300 ms+ | 500~1500 ms（视句长） |
| 口型 | ~150 ms + 音频缓冲 | 0（素材切换即时） |
| **合计感知** | ~1.5–2 s | **~2–3 s**（可接受；把 MIN_SILENCE_MS 降到 900 可抢回一截） |

成本（参考价，2026-09）：SenseVoice ≈ ¥0.3/小时语音；deepseek-chat ≈ ¥1–2/百万 token（输入）；
fish-speech ≈ ¥1.5/百万字符。日常聊天一小时约 **¥0.5–1.5**，比一张 GPU 便宜得多。

## 5. 界面改造清单（对应 s2s/demo）

1. **设置弹窗新增"☁ 云服务"标签页**：
   - 预设下拉（硅基流动 / DashScope / DeepSeek / OpenAI / 自定义），选即填三件套 base_url+model
   - STT / LLM / TTS 三组：base_url、model、api_key（password 框，localStorage 存储）
   - TTS 音色：预设音色下拉 + 自定义 voice ID 输入（填云端克隆音色 ID）；"上传 ref.wav 克隆"指引文案
   - **"复制启动命令"按钮**：按当前表单生成完整 `speech-to-speech serve ...` 命令复制到剪贴板
   - **"下载 cloud.env"按钮**：生成环境变量文件
   - 人设模板按钮（小雅模板一键填入 Instructions）
2. **顶栏模式徽标**：`☁ 全云端` 徽标 + 云服务是否已配置的状态点
3. **云模式数字人层（avatar-cloud.js）**：全屏视频背景（idle/speaking/listening 切换 + L1 包络微动效），
   左下角状态条沿用 avatar-sync 的样式语言；设置里可开关/换素材/选 L0/L1
4. Voice 下拉与云端 voice 联动；Instructions 保留（人设不变）
5. 其余 UI（orb 状态机、噪声门、字幕气泡、对话历史）不动——它们与模型位置无关

## 6. 运行方式变化

原：三窗口（CMD llama-server + WSL LiveTalking + WSL s2s）。
云：
```powershell
# Windows 本机（Python 3.12），无需 WSL、无需 GPU
pip install "speech-to-speech" uvicorn fastapi
# 按 cloud.env 或 UI 生成的命令：
speech-to-speech serve --stt openai --openai_stt_base_url https://api.siliconflow.cn/v1 ... 
# 前端
cd s2s/demo && npm ci && uvicorn server:app --port 7860
```
境外供应商（OpenAI）需系统代理；硅基流动/DashScope/DeepSeek 国内直连。

## 7. 风险与对策

- **CORS/密钥安全**：云 API 调用全部发生在本地编排服务进程里，浏览器不直接接触 key；UI 里填的 key 只存 localStorage 并用于生成命令/环境文件。
- **API 形态差异**：OpenAI 兼容字段以 s2s 内置 handler 为准（`openai_stt_*` / `responses_api_*` / `openai_tts_*`）；DashScope 用其 OpenAI 兼容模式端点。
- **TTS 采样率**：Realtime 通道统一 24kHz，s2s 的 openai TTS handler 已处理重采样；如遇变调按 README 提示调 `sample_rate`。
- **断网**：云端方案断网即哑——这是与"完全免费本地版"的本质取舍，文档里如实标注。
