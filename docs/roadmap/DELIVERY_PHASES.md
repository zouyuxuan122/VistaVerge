# 分阶段交付路线

2026-09-18 / 待审批。以阶段出口而非虚假精确工期推进。每个领域包制作与执行分离；未列出完整任务文件的名称只是路线候选，不是可执行控制包。

## 阶段0：本轮规划基础

已开展：只读代码/开源调研，私有GitHub仓库创建，本地Git初始化，需求与最高设计/子系统/质量文档。补充制作 `FOUNDATION-01` 草案。没有提交/推送、改产品代码或验证新功能。

出口：文档链接和需求可追踪、重要审阅问题已处置、初包每项有文件域/验门/状态；明确缺失真实资源。不把计划获阅/用户说“继续”解释成执行全部开发。

## 阶段1：可测试工程与共同合同

### FOUNDATION-01（本轮唯一完整任务草案）

先把现有音频采集用真实行为单测锁住，再修复已发现类型/取消参数错误，最后固定小范围运行时事件schema与代际取消测试。无UI重构、无大模型、无外部账号。详见[控制包](../../工程控制/FOUNDATION-01/00_README.md)。

### SECURITY-DATA-01（待制作）

凭据安全迁移、收紧CSP/原生HTTP、去掉生产假麦克风授权参数、用户数据目录与SQLite迁移/备份。必须在真实语音/第三方插件上线前完成。权限与数据合同先冻结，再制作文件互斥任务与机器门。

### RUNTIME-01（待制作）

受管理Node进程、认证IPC、会话/任务单写、生命周期与崩溃恢复。测包体、启动、资源；若Tauri/WebView2出现可复现阻断再用ADR评估Electron，不预先迁移。

## 阶段2：主体验与语音（最高优先）

### EXPERIENCE-01（待制作）

Vue组件化迁移、左电脑屏幕/右真实VRM/底部悬浮椭圆导航、聊天剪贴板与分支、手绘/写实主题。先有合法VRM最小场景，再制作精致电脑与动作，不能静态占位验收为最终人物。

### REALTIME-01（待制作）

流式LLM、渐进ASR/端点能力、分句/流式TTS、AEC与明确半双工降级、全状态取消、播放账本/时钟/口型。对Qwen3/FireRed/IndexTTS2.5分适配器，不等所有模型才测第一条真实闭环。

出口：真实对话和实体模型联动、UI正常操作、低延迟/发音/CER/打断/误触发报告。资产或服务缺失只能通过部分测试；相关真实门BLOCKED。

## 阶段3：记忆、感知与学习陪伴

### MEMORY-SENSE-01（待制作）

SQLite来源/时效/tag数据、FTS中文短词、embedding适配与向量影子索引、scope、纠错/忘记/恢复，模型主动检索。先本地确定性检索，再可选reranker与有界子智能体；不给热路径强塞多层LLM。

### TEACHER-COMPANION-01（待制作）

资料→引用→诊断→练习→批改→错题→复习，角色卡/可控记忆/日常共同活动。根据阶段2语音能力加入口语，评分独立评测器另列阻塞。出门情境先用测试天气/HA录制fixture，之后真接口验证。

### PLUGIN-01（待制作）

SDK、示例、权限、声明式与可信原生插件分层、仓库源、安装事务、版本兼容和卸载。内部教师/感知插件反证SDK是否真正可用；公开市场前完成信任和安全门。

## 阶段4：隔离电脑操作与MC

### CONTROL-01（待制作）

先独立浏览器真实输入+应用内大光标+帧版本+宿主观察器；再隔离原生应用原型。Windows能力矩阵、焦点不干扰、合法账号与输入租约是先决门。不会把UIA或虚拟桌面直接宣布为隔离。

### MINECRAFT-01（待制作）

Java版固定兼容矩阵，Mineflayer连接/跟随/停止→采集合成→搭建→避险/受击/恢复→同时角色语音交流。账号/服务器许可、自动化标识、版本/种子/样本固定。高频行为不依赖LLM。

出口：真实桌面/浏览器业务完成且宿主不中断，真实MC任务可复核与并行语音稳定；失败记录保留。首批稳定场景交付，不承诺所有应用/MC版本。

## 阶段5：连接器与分发维护

### CONNECTORS-01（待制作）

Home Assistant、城市天气、温度/灯光/出门提醒、GitHub PR/Issue用户配置巡检。QQ/微博从草稿扩展到合法API或隔离环境授权发送，不能无限期用草稿冒充实现发送。

### RELEASE-01（待制作）

原创图标与合法资源获取、定制NSIS、首次向导、模型按需下载、签名应用/插件更新、数据库恢复、兼容矩阵与诊断、离线失败行为。初步发布方案从阶段1就约束目录与数据，功能完成后再进行真实发行演练。

## 研究线：不拖累核心闭环

### ASSET-GENERATION-RD（只读/原型审批后进行）

合法多视角图片→一致几何→拓扑/UV/材质→骨骼与权重→口型/表情→动作→VRM导出→验证。按至少10组授权人物样本评估身份一致、缺面/手部、可绑定率、人工修复时长、显存/耗时/许可。仅外形生成成功不算“一键可用角色”。高质量失败则提供导入/校验与半自动Blender流程，实验入口明确标注。

其他游戏由社区GameAdapter扩展；跨设备、自动环境观察等新增范围需单独需求与隐私设计。

## 依赖顺序与执行纪律

FOUNDATION → SECURITY-DATA/RUNTIME → EXPERIENCE/REALTIME → MEMORY/TEACHER/PLUGIN → CONTROL/MC → CONNECTORS/RELEASE。

这是逻辑依赖，读审可并行；同一工作区写入串行。开发子智能体一个任务一个文件域，运行时子智能体按预算调度，二者不可混用。每批都有错误/断线/取消/迁移测试和真实体验调优，不设独立“最后再补测试”阶段。

产品代码提交与推送需明确授权；阶段0未因创建仓库而上传旧素材。新项目许可证、品牌/声音授权、正式签名和隔离Windows许可在对应真实门前解决。
