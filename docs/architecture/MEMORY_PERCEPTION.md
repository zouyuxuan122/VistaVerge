# 本地记忆、索引与五感情境系统

状态：待审批 / 未实施。上层：[最高设计](../../VISTAVERGE_DESIGN.md) §2、§7；[系统合同](SYSTEM_CONTRACTS.md)。

## 1. 目标与非目标

用户可以问“我之前说资料放哪儿了”，模型能主动查本地记忆；标签支持工作、学习、生活、出行、人物、项目等分类。用户说“我要出去了”时，天气与出行记忆可以共同形成一条自然提醒。

不是保存所有录音、让模型无限查看全部私人资料，也不是把向量库误认为准确事实库。不引入首期图数据库或专门常驻的向量服务器。索引模型只做检索表征，不负责宣布事实真伪。

## 2. 本地数据与索引

**真相层：SQLite 单写服务。** 逻辑实体：

- Memory：id、owner/scope、kind（事实/偏好/事件/待办）、内容、创建/观测时间、有效期、状态、版本、敏感级别。
- Source：会话/消息/资料锚点/设备/用户手填，可靠性说明；ASR 有原始置信和修订信息。
- Claim：对象/属性/值、肯定或否定、有效区间、supersedes；保留“以前喜欢、现在戒了”的时间关系。
- Tag / MemoryTag：多对多，用户可增删改；自动标签标明来源。标签不是访问权限，scope 单独执行。
- MemoryLink：支持/冲突/补充/导出于；先做一跳与来源追踪，不承诺全图推理。
- Reminder：触发条件、证据、去重键、quiet-hours、状态与用户反馈。
- IndexGeneration：模型 ID/权重 hash/维度/分词版本、状态、进度、校验记录。
- Tombstone：删除的 opaque ID、版本与恢复约束，不保留被遗忘的正文或标签内容。

全文与向量是**可丢弃重建的派生层**。FTS5 采用带中文验证的方案：默认评估 trigram + 标签/实体精确匹配，对一到两个汉字查询有受范围限制的精确/子串或分词回退；不能忽略 trigram 对短词的限制。若中文预分词效果更好，通过版本化索引适配器替换。不得将 unicode61 默认行为视为已验证的中文检索。

向量后端优先评估 sqlite-vec，但其版本成熟度、发布许可、查询能力和本机规模需测；维度来自选定 embedding 模型，**不写死 1024**。中文优先的 BGE 系列与 multilingual-e5 是候选，模型卡/权重来源/ONNX兼容/许可/CPU耗时尚需落地基准；不默认每台机器运行大模型。

## 3. 混合检索流程

1. 接受查询、tag 的 any/all 模式、时间窗、kind、topK 与请求者上下文。
2. 先计算允许 scope；模型不能传一个更大 scope 获得额外读取权。
3. 在允许范围内做 FTS 与向量召回，合并去重、RRF 融合；可选本地 reranker 仅在候选歧义时加载。
4. 状态/时效/否定冲突/权限过滤在结果返回前再次执行；采用索引分区或有上限的超额召回避免简单 topK 后过滤漏光结果。
5. 返回证据卡：memoryId、版本、摘录、来源、时间、当前/历史/冲突标志；不直接返回全库。

`memory.search(query, tags, tagMode, timeRange, kinds, topK)` 默认 topK=8，上限20与输出字符预算双重限制。无 embedding 时关键词+标签仍可用，并显示降级状态。用户主动搜索结果与 Agent 使用同一权限和删除语义。

## 4. 写入与纠错

用户手工记忆可直接提交；模型只能 `proposeWrite`，由唯一写入服务做去重、冲突、敏感级别和来源校验。明确命令“记住”与普通聊天自动提取分开策略；密码、密钥、金融认证信息不作自动记忆。

背景电视、低置信转写、自播语音不能直接转为长期用户事实。事件观测保存在短期状态缓存，只有有意义的变化/用户请求才晋升为记忆，避免每次温度变化写入永久库。

“我戒咖啡了”使旧当前偏好失效，但允许历史查询带时间回溯；“我没说过喜欢咖啡”是纠错，应修正错误来源。来源相互矛盾时展示冲突，不平均成一个看似可信的数字。年龄、关系、健康等敏感推断不得由弱证据自动固化。

## 5. 忘记、备份与索引重建

遗忘事务：限制后续召回 → 删除活动正文/来源片段或按请求保留不涉敏审计 → 清 FTS/向量 → 清缓存与派生摘要 → 通知活跃任务撤销相关上下文 → tombstone → 完成状态。

FTS/向量可能不受普通外键自动级联，需显式事务或事务 outbox；旧索引版本若无法即刻清理先禁止查询，不能只删主表就宣布完成。重建只包含当前允许记录，不用全表 FTS rebuild 恢复已软删除内容。

切换 embedding 建立影子索引、记录进度、原子切换；旧版本查询保持一致，失败保留旧索引。备份用 SQLite Backup API/VACUUM INTO 的一致快照，不裸复制运行中的主 db。备份默认本地、访问受控；普通 SQLite 不是加密仓库，磁盘加密/额外加密能力须明确。

备份也可能含已遗忘内容：提供清除历史备份或保留旧备份的明确选择；恢复必须应用最新可用 tombstone/隐私删除账本，验证删除不复活。无法覆盖用户已复制到应用外的文件，界面说明边界，不许保证遥不可及的删除。

## 6. 五类感知与证据统一

| 感知 | 可信输入 | 限制 |
| --- | --- | --- |
| 听觉/对话 | 用户语音、文本、显式意图 | 常听需授权，背景不算用户说过 |
| 视觉/应用 | 授权窗口、文件、游戏状态 | 无摄像头时不推断表情或位置 |
| 环境 | HA 温湿度、照度、设备状态、天气 | 设定值不等于实测，过期不算现在 |
| 时间/活动 | 日程、任务、出门/休息意图 | 用户改变主意要取消旧提醒 |
| 关系/经历 | 授权记忆、偏好、承诺 | 记得不等于确定当前仍成立 |

统一 Observation：`sourceId, kind, value, unit, observedAt, expiresAt, reliability, scope`。前台显示来自何设备/城市/时间；定位只需天气所需粒度，不默认精确 GPS。

## 7. 主动提醒流程

本地事件/规则候选 → 按需检索与天气并发 → 证据与反证检查 → 通知优先级/安静时间/去重 → 一条简洁提醒 → 反馈（有用/不用再提醒/已完成）。

不硬性要求两个传感器才允许说话：用户明确“我要出门”加有效天气已足够。单独天气变差不应每次主动插话。默认同一出门会话同类提醒一次，用户补充重要新事实可更新；非紧急关怀默认每小时最多两次，可调。普通回复不计入主动提醒额度。关键安全提醒必须有独立明确规则，不能随便贴“紧急”绕过静默。

例：用户上午说“下午带签字材料去学校”；下午说“我要出去了”。检索今天任务和城市天气，回答“路上可能有雨，带把伞；上午说的签字材料也记得拿上”。已知已带伞时只提醒材料；不知道材料是否带齐时用提醒而不是断言忘记。

空调16℃持续一小时：检查设备制冷状态、设定持续区间、当前数据新鲜度；有实测/占用则补充，没有则说“空调设定16℃已经一段时间，要不要调高一点”，不声称实际室温或健康影响。断线区间不自动算连续证据。

## 8. 子智能体与成本

Recall/Scene/Task 辅助智能体默认只读，各带 scope、deadline、token/tool预算，最大并发与递归遵守系统合同。出门提醒热路径优先已有新鲜状态与本地标签/FTS，warm检索目标预算150ms，额外语义检索目标500ms；外部天气/子智能体富化默认最多等待1秒（可校准），超时先以已验证信息短答，缺证据不编造。后台结果只在仍有用、未超时且同一有效场景时合并，不能不断补说打断用户。结构化证据交给主会话整合，所有写提议归一；任一取消代际失效后不得写入/发出提醒。

常驻只做事件监听和确定规则；embedding 低优先级批处理，天气缓存遵守 TTL；不每秒轮询 LLM，不每次传完整记忆库。高质量模型按歧义调用，保证效果与预算可观测。

## 9. 验收数据集

- 中文“伞/钥匙/项目”短词与自然语言同义查询，混合检索和纯关键词回退均有已知目标。
- 标签 any/all、scope 越权、跨角色/跨项目隔离：不允许结果或片段泄漏。
- 否定/更正/新旧偏好、过期待办：当前回复不使用过期事实；历史查询明确时间。
- 删除后关键词、语义、摘要、活跃任务、重建和备份恢复均不复活；中途故障不谎报已忘记。
- 模型维度变更、索引失败/断点恢复、1万/5万/10万条规模基准，不提前承诺十万条恒定速度。
- 电视声、自播语音与“别记这个”不进入长期用户事实；真实语音错误单独统计，不保证所有噪声零误识别。
- 出门+雨+材料、已带伞反证、取消出门、天气过期/无定位、HA断线、安静时间与去重全覆盖。
