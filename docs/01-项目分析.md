# AI 赛博女友 · 项目分析

> 分析对象：freedidi.com/24984《AI 赛博女友！本地部署教程》所部署的项目
> 工作区来源：`deploy-package/`（博客一键部署包，已解压）+ `s2s/`（上游 huggingface/speech-to-speech 源码）

## 1. 一句话概括

一个"会说话、有口型的 AI 数字人"网页：背景是数字人视频，中间是语音球（orb），用户对着麦克风说话，
她用克隆音色回答、嘴型跟着动。**全流程跑在本地 GPU 上（最低 8G 显存）**——这正是本工作区要改造成
"全云端、核显也能跑"的原因。

## 2. 真实技术栈（来自部署包脚本，非教程描述）

| 组件 | 实现 | 位置 | 端口 | 算力 |
|---|---|---|---|---|
| 大脑 LLM | llama.cpp `llama-server` + Qwen3-14B/8B/4B GGUF | Windows 侧 | 8090 | ~9 GB 显存 |
| 编排管线 | **huggingface/speech-to-speech**（PyPI 包 `[faster-whisper]` extra） | WSL `~/s2s/.venv` | 8765 | VAD+调度，CPU/GPU |
| 耳朵 STT | faster-whisper large-v3（s2s 内置 handler） | 同上 | — | ~3 GB 显存 |
| 嘴巴 TTS | Qwen3-TTS-12Hz-1.7B-Base（音色克隆 ref.wav + REF_TEXT） | 同上 | — | ~4 GB 显存 |
| 前端 UI | HF Space **smolagents/hf-realtime-voice**（语音球界面） | WSL `~/s2s/hf-realtime-voice` | 7860 | 纯浏览器 |
| 口型同步 | **lipku/LiveTalking**（wav2lip256，WebRTC 推流） | WSL `~/livetalking` | 8010 | ~1.3 GB 显存 |
| 粘合层 | 部署包 `avatar-sync.js`（劫持 WebSocket + 背景层注入） | 浏览器 | — | 无 |
| 素材 | idle.mp4（闭嘴底版，Wan2.2 图生视频）+ ref.wav（克隆音源） | 部署包 | — | — |

## 3. 数据流（一次对话的完整路径）

```
浏览器(7860, orb UI)
  │ ①麦克风 PCM 40ms 分块（前端噪声门在 capture worklet 里）
  │ ②WebSocket  ws://localhost:8765/v1/realtime   ← OpenAI Realtime GA 协议
  ▼
s2s server(8765)  VAD(silero) → STT(faster-whisper) → LLM(chat-completions) → TTS(qwen3)
                                        │                      │
                                        ▼                      │
                          llama.cpp :8090  /v1/chat/completions │
                                                                │
浏览器 avatar-sync.js（关键粘合层，install-voice.sh 注入 index.html）
  ③ 劫持 window.WebSocket，截收 response.output_audio.delta（base64 PCM16）
  ④ stopImmediatePropagation() 吞掉 s2s 本地播放（防双声）
  ⑤ 整段拼成 WAV → POST {LiveTalking:8010}/humanaudio
  ▼
LiveTalking:8010  wav2lip256 实时生成口型
  ⑥ WebRTC 音视频流回浏览器 → 全屏 <video> 背景层 + 独立 <audio> 出声
  ⑦ input_audio_buffer.speech_started（用户插话）→ POST /interrupt_talk 打断
```

要点：
- 前后端之间是**标准 OpenAI Realtime 协议**——这是云端化最大利好，协议层不用动。
- avatar-sync.js 不是"同步"，而是**转投**：s2s 出的音频被转手给 LiveTalking，由它统一发声+口型，
  牺牲约一段音频的缓冲延迟换取音画同步。
- `install-voice.sh` 的"补丁"= 给 Space 的 server.py 加一条 `/avatar-sync.js` 静态路由 + 在
  index.html 插 `<script src="/avatar-sync.js"></script>`。

## 4. start-voice.sh 的关键启动参数（改造的基准）

```bash
speech-to-speech \
  --mode realtime \
  --stt faster-whisper --faster_whisper_stt_model_name large-v3 --faster_whisper_stt_gen_language zh \
  --language zh \
  --llm_backend chat-completions --model_name Qwen3-14B \
  --responses_api_base_url http://127.0.0.1:8090/v1 \   # ← 已经是 OpenAI 兼容协议！
  --responses_api_api_key '' --responses_api_stream \
  --tts qwen3 --qwen3_tts_model_name Qwen/Qwen3-TTS-12Hz-1.7B-Base --qwen3_tts_language zh \
  --qwen3_tts_ref_audio ~/s2s/ref.wav --qwen3_tts_ref_text '……原话……' \
  --thresh 0.6 --min_speech_ms 500 --min_speech_continuation_ms 192 \
  --min_silence_ms 1200 --speech_pad_ms 300 --speculative_reopen_ms 2500 --short_segment_merge_ms 800
```

三个重要事实：
1. **LLM 用的本来就是 `chat-completions`（OpenAI 兼容）后端**，llama.cpp 只是它的一个 base_url。
   → 换成 DeepSeek/硅基流动/DashScope 等，只改两个参数。
2. VAD 手感参数（min_silence_ms 等）在编排层，与模型在哪无关，云端化后原样保留。
3. TTS 音色克隆依赖本地模型吃 ref.wav+REF_TEXT；云端 TTS 的克隆方式不同（见 02 方案文档）。

## 5. 前端界面结构（s2s/demo = hf-realtime-voice 同源）

| 文件 | 职责 |
|---|---|
| `index.html` | 顶栏（Tools/Chat/Settings）+ 中央 orb（state-idle/listening/…/ai-speaking 九态）+ 噪声门弧形拖杆 + bubble 字幕 + 设置弹窗 |
| `main.js` (1691 行) | 状态机、设置持久化(localStorage)、设备枚举、工具(搜索/摄像头)、连接编排 |
| `s2s-realtime-client.js` | OpenAI Agents SDK RealtimeSession 适配层，WS/WebRTC 双传输 |
| `worklets/mic-capture.js` | 麦克风采集 + 前端噪声门（Settings 里的 NOISE GATE 就是它） |
| `worklets/audio-playback.js` | TTS 音频回放（24kHz PCM） |
| `ws/orb-visualizer.js` | 语音球频谱可视化 |
| `server.py` | FastAPI：静态托管 + /api/config + HF LB 代理（可选） |

设置面板现有字段：Server URL / Transport / Voice(Qwen3 音色名) / 麦克风 / 扬声器 / Noise Gate / Instructions。
这些 Voice 名（Aiden/Vivian/…）是 Qwen3-TTS 内置音色——云端 TTS 需要换成云端音色体系。

## 6. 上游 s2s 已支持的"模型即插即用"清单（backend_registry.py）

- **STT**：whisper / faster-whisper / parakeet-tdt / paraformer / qwen3-asr / **openai（OpenAI 兼容 HTTP 转写）** / openai-realtime / vllm-realtime
- **LLM**：transformers / mlx-lm / **responses-api（云端）** / **chat-completions（任意 OpenAI 兼容云端）**
- **TTS**：chatTTS / kokoro / qwen3 / facebookMMS / omnivoice / pocket / supertonic / **openai（OpenAI 兼容 TTS）**

结论：**三件套全云端所需的后端 handler 上游已全部内置**（`openai` STT / `chat-completions` LLM /
`openai` TTS），云端化主要是"配置 + 界面 + 口型替代"，不需要给管线写新模型代码。

## 7. 本地素材清单（deploy-package/）

- `avatar-sync.js`：LiveTalking 粘合层（12 KB，全功能可读）
- `idle.mp4 / listening.mp4 / speaking.mp4`：三段状态视频（704×896 竖版，各 5 秒）
  ——cloud 模式可复用为"状态切换"数字人层素材
- `ref.wav / ref.mp3`：克隆音源（云端 TTS 建音色时直接上传它）
- `wav2lip256.pth (214MB) / wav2lip256_avatar1.tar.gz (353MB)`：LiveTalking 权重，云模式不需要
- `README.txt / install-voice.sh / start-voice.sh / start-livetalking.sh`：部署脚本
