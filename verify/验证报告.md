## 端到端时间线（Config B 实测，协议事件）

```
0.04s  session.created / session.updated     ← WS 连接 + 会话协商
1.17s  input_audio_buffer.speech_started     ← VAD 检测到语音（ref.wav 真人声）
13.04s input_audio_buffer.speech_stopped     ← min_silence_ms=1200 断句生效
14.12s conversation.item.input_audio_transcription.completed
       转写: "靠飛了,你終於上線了我記開心,又有點願你嗯,小雅一個人在這裡等你等得都快委去死了"
       （faster-whisper tiny 的真实输出；REF_TEXT 原文：靠杯了，你终于上线了……）
15.06s response.created → transcript.delta   ← LLM 回复流式生成（网关收到 chat.completions）
17.77s response.done                         ← 77 块 / 13.4s 真实微软云端人声输出完毕
```

语音进 → 识别 → 回复 → **云端人声出**，全程 4.6 秒（断句 1.2s 后到回复完成）。

```
STT: fields={'response_format':'json','model':'mock-asr','language':'zh'} + multipart WAV  ← 渐进式累计上传与官方文档一致
LLM: stream=True model='mock-chat' messages=[...personality + user text...]
TTS: model='mock-tts' voice='user:my-clone-voice-id' fmt='pcm' input='喂，你终于上线了…'
```

与硅基流动 / OpenAI 等真实供应商的接口形状一致——**换 Key 即换真云**。

## 如实说明（未验证项与原因）

- **真实付费云端到端**（硅基流动/OpenAI 的 STT/LLM）：需注册获取 Key，本机无法自主完成；
  但请求形状/参数/协议已由网关逐字验证，UI 的「复制启动命令」与 `cloud.env` 填 Key 即用。
- **浏览器假麦克风完整回合**：Chromium 合成蜂鸣的间隔小于 1.2s 停顿阈值，回合永远不结束
  （一直 user-speaking）——这是假音源的特性，不是缺陷；真人说话即正常断句（协议层已用
  真人语音验证过两轮）。
- 验证过程中发现并修复：ref.wav 实为 44.1kHz 立体声（需按教程转 16kHz 单声道）、
  `session.update` 需回显 `session.created` 的完整 session 对象、协议里转写事件名为
  `response.output_audio_transcript.delta`。
